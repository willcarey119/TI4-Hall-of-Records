## Phase 4 — Agenda tab full scope (V1.1 headline feature) ✅ COMPLETE

**Goal:** Ship the full cross-game Agenda analytics experience, using the per-game `AgendaSection`'s editorial broadsheet aesthetic as the design north star (per user: *"The Agenda View is my favorite in the entire app, and I want more Agenda improvements based on how we have it here."*).

**Acceptance:** The `/agenda` route shows: per-agenda cross-game comparison; vote tallies; VP impact; faction voting patterns; agenda timing (round); riders. Visual language consistent with the per-game `AgendaSection`.

**This phase deserves its own detailed plan written when we start it** (using the `superpowers:writing-plans` skill). What follows is the scope sketch.

### Sub-deliverables (per ROADMAP §V1.1 Step 5 + walkthrough)

- [ ] **A1 — Per-agenda cross-game comparison view.** When clicking on an agenda in the list, show how it resolved in each game it appeared. Vote counts, outcome, round, key voters.
- [ ] **A2 — Vote tallies per agenda resolution.** For binary agendas: For votes vs. Against votes per faction. For elect-type: votes per elected target.
- [ ] **A3 — VP impact view.** Which agendas resulted in VP changes; net VP swing per outcome (this connects to the agenda VP handlers we built in v1.07/v1.08).
- [ ] **A4 — Faction voting patterns.** Per faction, across all appearances of each agenda — how did they vote? Senate Power Index extension.
- [ ] **A5 — Agenda timing.** Round-of-game for each appearance. Bar chart or scatter — does early vs late agenda timing correlate with anything?
- [ ] **A6 — Riders tracked.** Which riders were played on which agendas; outcome.
- [ ] **A7 — Visual language consistency** with per-game `AgendaSection` — large readable agenda blocks, vote columns, effect text, riders inline.
- [ ] **A8 — Definitions / legend** at the top of the page (user: *"We probably need a definitions section at the top"*).
